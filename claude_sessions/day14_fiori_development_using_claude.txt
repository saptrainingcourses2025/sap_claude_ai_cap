● I found a significant pre-existing bug, unrelated to the app I'm building,
  that blocks the Admin lock/unlock feature (AC #6) from working in real usage.

  What's broken: Every custom action/function in
  srv/handlers/user-management.handler.js (lockUser, unlockUser, createUser,
  resetPassword, assignRole, unassignRole) uses bare SELECT.one.from(Users) /
  UPDATE(Users) without first calling cds.connect.to('db'). When run as a real
  server (npm start), these fail with "Can't execute query as no primary 
  database is connected." — I verified this against the actually-running server
  for both createUser (POST action) and unlockUser (GET function). Plain entity
  reads (e.g. GET /catalog/Travellers) work fine, and Jest's cds.test() harness
